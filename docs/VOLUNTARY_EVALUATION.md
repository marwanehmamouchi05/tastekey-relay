# Voluntary evaluation: real answers before results

No participants have been recruited. Public ballots and synthetic answers must not be entered as volunteer responses. This workflow is ready for consenting adults who choose to participate; no email, name, private browsing history or sensitive background is needed.

1. Explain that participation is optional, stopping is allowed at any time, recommendations can be wrong, and no purchase is involved. Use a random participant alias kept locally. Ask permission before retaining anonymous answers; do not upload answers automatically.
2. Before opening Suggestions, ask for three reviewed film references and up to five other films the person already likes. Record those held-outs privately before retrieving recommendations. A missing film is unknown, not a negative rating.
3. Record at most one clarification answer, including “not sure” or “none.” Do not invent an answer. A skipped question leaves uncertainty intact. Store the question text and actual answer separately from the held-outs.
4. Freeze the candidate retrieval and ranking implementation, catalogue baseline and measurement plan before the first session. Exclude reviewed seed IDs from suggestions. Never send the person's alias or held-outs to Qloo. Use identical initial seed information for each arm; report the extra clarification question rather than treating unequal budgets as equal.
5. Compare a predeclared independent content/editorial catalogue baseline, unmodified Qloo, and the conservative confirmed-metadata reranker. Keep retrieval recall separate from ranking. Use an organizer to hide arm names and randomize display order; the app's existing Proof view is an exploratory recorder, not a blinded experiment.
6. Ask about usefulness only after the person has selected preferences. Any correction arm must use an actual correction from that person, with the same initial pool where appropriate. Record no correction result if none is given.
7. Retain missing retrievals and failures. Report Hit@3, recall, reciprocal rank, binary nDCG only for binary labels, question count, elapsed times and actual provider calls. Use graded nDCG only if genuine graded judgments were collected. Report participant count separately from repeated observations.
8. Let participants inspect/delete their locally stored answers. Publish only consented anonymous aggregates and a complete protocol. Do not publish raw preference graphs, cookies, invitation links or accounts. Reconfirm permission before any later sharing.

For Studio, use the existing persisted Human evaluation rubric on exact investigation IDs, with consenting real business owners who check operational feasibility. Reviewer aliases are self-reported and do not establish independent participation. Synthetic inputs can validate budget/evidence contracts, not demand, usefulness or revenue.

This document does not manufacture an experiment result. Genuine independent human evidence remains outstanding.
