# Data flows and security boundaries

October 28 readiness review found and fixed two concrete issues: request bodies are now capped while streaming at 50,000 UTF-8 bytes, including requests without Content-Length; widget confirmation now waits for a source/origin/state/widget-bound acknowledgement and reports expiry or missing acknowledgement honestly. Five bounded-reader unit cases and the expired/missing-ack browser cases pass. The evaluation comparison also now uses only the authorized context and the production ranking helper. These are targeted checks, not an independent penetration test or security certification.

Model validation protects structure, assigned references, IDs, costs and ownership. It does not fact-check every sentence of AI advice; owner review and warnings about demand, rights, supply and capacity remain necessary.

## Enforced controls

- Record reads/writes and business/action relationships are authorized by tenant on the server. A visitor cannot select a tenant through the public API.
- Session tokens contain 256 random bits and are stored hashed, expire after 30 days, and use HTTP-only SameSite Strict cookies, Secure under HTTPS. Restoring a recovery code invalidates prior sessions. Recovery grants full workspace access; protect the code like a credential. It does not sync Personal localStorage.
- Writes require matching Origin. Bodies, strings, arrays, enum values and numerical constraints are bounded. Sensitive status values are never returned.
- Qloo uses an installed trusted script with an argument array and no shell. Calls have concurrency, hourly allowance and timeout controls. Raw subprocess errors do not reach clients.
- Model output is untrusted and validated. Explicit provider credentials, input/output limits, one SDK attempt and a persistent global daily allowance constrain model use. The production model identity is restricted by model resources, server IP and expiry. Configuration is unavailable after its declared expiry.
- Contexts exclude unverified, rejected, superseded and unrelated nodes. Revocation/expiry invalidates pending responses. Budgets do not go to Qloo; entertainment does not receive budget values.
- Personal deletion first withdraws contributions for the current private session, then clears local graph, grants, history, budgets, proof and quotes. If withdrawal fails, the interface reports failure. Lost cookies require recovery to access prior contributions. Studio deletion removes its records and revokes linked sessions/recovery codes.
- Audience invitations expire in 30 days. Only explicitly selected coarse categories are collected; repeat submissions from one verified account replace its prior contribution across sessions. Anonymous legacy contributions are excluded and team members cannot contribute to their own business audience. Withdrawal immediately removes contributions from reports. Daily maintenance physically deletes expired audience data and recovery codes.
- Reports require ten active verified-account contributions. A group is disclosed only at count >=10 and with a complement of zero or >=10. No email, individual IDs or suppressed total counts are returned. These controls are not differential privacy and do not establish independent humans.
- Verified sign-in uses HTTPS OpenID Connect discovery, PKCE S256, browser-bound single-use transactions, state, nonce, explicit signature verification, issuer/audience/expiry and `email_verified=true`. App sessions expire after eight hours. Membership and role checks occur on every authenticated request; revoked/expired sessions cannot fall back to anonymous ownership. Claiming a private workspace revokes old capabilities and recovery codes. See [identity](IDENTITY.md) for roles, invitations and provider boundaries.
- Nonce-based script CSP, private-page framing denial, restrictive browser permissions and HTTPS headers are deployed. Only public widget HTML permits its registered merchant origin and self through CSP `frame-ancestors`. The legacy global frame-denial header remains; modern browsers apply the CSP directive, while unsupported browsers fail closed. Inline styles remain allowed for React Flow positioning. React escapes text rather than interpreting model HTML.
- Logs contain operation path and exception type, not prompts or credentials. Traces preserve selected business inputs and public cultural evidence; exports contain private business data.
- Online SQLite snapshots are integrity checked, private and retained on the host for roughly seven days. Deletion cannot recall exports or already copied backups. Backups can retain withdrawn/expired data until retention ends.

## Limits before broader production use

Anonymous exploration still uses capability sessions and recovery; a stolen cookie or recovery code grants access. Verified team workspaces disable capability recovery and enforce owner/admin/editor/viewer roles. Cognito provides email-account sign-in, not business-registration verification, corporate federation or SCIM. Shared browser profiles share access until sign-out. Personal data is unencrypted browser storage accessible to same-origin scripts. Client source security, dependencies and device protection remain important.

SQLite assumes persistent disk and one app replica. Host snapshots alone do not survive host loss; a separate off-host backup and tested restoration are required. Session/Qloo request counters are process-local and reset on restart; model daily usage is persisted. Session throttling trusts proxy forwarding headers, which the reverse proxy must sanitize. Distributed enforcement and longer-term retention policy remain future work.

Verified email accounts can still belong to the same person; account deduplication is not proof of unique humans. Small-count suppression cannot prevent every inference attack. Existing exports cannot be recalled after withdrawal. No real customer dataset or independent privacy audit is claimed.

Optional models receive explicitly submitted text or business briefs. Avoid customer identifiers or sensitive records; provider retention follows provider terms. Cultural search text is user supplied and is not an automatic identifier-redaction service. Human reviewer aliases and owner-reported outcomes are not independently audited.

Tests cover cross-tenant access, cross-origin writes, invalid/recovered sessions, consent expiry/revocation, suppression, withdrawal, protected model fields and backup integrity. Passing these tests is not a penetration test.

## Optional website integrations

The extension has user-activated temporary page access and local storage, no broad host access, background scanning, remote scripts or analytics. It copies only stated/confirmed labels/categories from the trusted TasteKey origin; filtering checks current visible result cards locally. Stored extension likes can be deleted. It cannot guarantee current adapter compatibility or independently verified page prices.

Only owners/admins connect and enable public widgets; writer roles manage offers. Public responses exclude private business records and unselected drafts. Offer links stay on the registered HTTPS origin. Visitor matching uses explicitly selected labels/categories within a TasteKey-owned frame; messages bind popup source, exact origin, widget ID and expiring random state. No visitor list, event log or profile is sent to the merchant or persisted by the widget. Selected likes expire after fifteen minutes or frame close and can be cleared immediately. Merchant pages can observe their own incoming clicks and have their own privacy policies. See [integration details and limitations](INTEGRATIONS.md).
